# Googleフォーム仕様

## 1. 共通要件

- 通常登録フォームと修正申請フォームを分ける。
- 学校Googleアカウントへのログインを必須とする。
- メールアドレスを自動収集する。
- 回答者自身の学籍番号と氏名を必須入力とする。
- フォーム送信では正式名簿を更新しない。
- 回答はすべて承認待ちとして保存する。
- 競技設定からGASでフォームを生成する。
- フォームの手動編集は原則禁止し、設定シートから再生成する。
- フォームは年度ごとに新規生成し、下書き確認後に公開する。
- 再生成に成功した場合は、古い生成フォームの回答送信トリガーを削除し、古いフォームをゴミ箱へ移動する。
- 通常・修正フォームは競技単位の分割処理で作成し、時間主導トリガーで完了まで継続する。
- 作成途中のフォームは公開せず、フォーム設計の現行フォームIDへ設定しない。2フォームの項目と分岐がすべて完成してから一括で切り替える。
- 質問は表示名ではなく`フォーム項目対応表`の`field_key`で内部項目へ対応させる。
- 入力者と選手のすべての学籍番号欄に、半角数字4桁だけを受け付ける回答の検証を設定する。
- 設問作成はGoogle Forms APIの`batchUpdate`で競技単位に一括追加し、APIで扱えない学籍番号の回答検証とセクション終了後の送信動作だけを`FormApp`で設定する。
- Forms APIへ送るのはフォーム構造と競技設定だけとし、生徒マスターやフォーム回答を送らない。回答の取込経路にはForms APIを使用しない。

通常・修正フォームを非公開の下書きとして生成し、項目対応表を保存する。公開確定の直前に実フォームの回答項目を全件検査し、設問ID、表示名、形式、未登録設問の差分があれば公開を中止する。設定の詳細は[settings.md](settings.md)を参照する。

## 2. 通常登録フォーム

### タイトル

`{年度}年度 体育祭 選手登録フォーム`

### 冒頭説明

```text
各クラスの代表者が、クラス全員分の選手登録を行うフォームです。

・クラス内で登録内容を確定してから入力してください。
・学籍番号と氏名は、生徒本人に確認してください。
・送信後、入力内容はすぐには名簿へ反映されません。
・体育祭スタッフ招集パートが内容を確認し、承認した後に反映されます。
・入力間違いを見つけた場合は、このフォームを再送信せず、修正申請フォームを使用してください。

締切：{締切日：yyyy/MM/dd(曜)}
問い合わせ先：体育祭スタッフ 招集パート
```

### セクションA：確認事項

必須チェック:

- クラス内で登録内容を確認した
- 学籍番号と氏名を本人に確認した
- 通常フォームを重複送信しない
- 修正は修正申請フォームから行う

### セクションB：回答責任者

| 項目 | 形式 | 必須 | 備考 |
|---|---|---:|---|
| 回答者の学年 | プルダウン | はい | 1〜3年 |
| 回答者の組 | プルダウン | はい | 1〜8組 |
| 回答者の学籍番号 | 記述式 | はい | 半角4桁 |
| 回答者の氏名 | 記述式 | はい | 生徒マスターと照合 |
| 登録対象クラス | プルダウン | はい | 学年・組 |
| 代理入力か | ラジオ | はい | 自分のクラス / 別クラス |
| 代理入力理由 | 段落 | 条件付き | 別クラスの場合必須 |

学籍番号形式:

```regex
^[0-9]{4}$
```

表示文:

```text
4ケタの学籍番号を数値で入力してください
```

この回答の検証は、通常登録フォームと修正申請フォームの`field_key`が`_student_id`で終わる全質問（入力者の学籍番号を含む）へ設定する。存在しない学籍番号や所属不一致は、フォーム送信後の検査処理で別途判定する。

### セクションC：学年分岐

回答者が選択した登録対象学年に応じて、該当学年の競技セクションへ移動する。

- 1年 → 1年競技
- 2年 → 2年競技
- 3年 → 3年競技

全学年共通競技は各学年のフローに含める。

### セクションD：競技入力

競技ごとに以下を生成する。

- 競技名
- 区分（男子・女子・混合・指定なし）
- 必要人数
- 走順または役割
- 選手ごとの学籍番号
- 選手ごとの氏名
- 未確定可否

選手欄:

| 項目 | 形式 | 必須 |
|---|---|---:|
| 学籍番号 | 記述式 | 設定による |
| 氏名 | 記述式 | 学籍番号と同じ |
| 登録状態 | ラジオ | 欠員許可時のみ |

登録状態:

- 選手を登録する
- 現在調整中
- 出場しない

空欄だけで欠員を表現しない。

### セクションE：最終確認

- クラス内で最終確認済み / 一部調整中
- 連絡事項
- `入力内容を確認し、この内容で提出します`チェック

### 送信後メッセージ

```text
選手登録を受け付けました。

この時点では名簿には反映されていません。
体育祭スタッフ招集パートが内容を確認し、承認した後に反映されます。

入力間違いを見つけた場合は、通常フォームを再送信せず、修正申請フォームから申請してください。
修正申請フォーム：{URL}
```

### 同一クラスから複数回答

- 自動で最新回答を採用しない。
- すべて承認待ちへ保存する。
- `同じクラスから複数の回答があります`と警告する。
- 送信日時と全選手内容を同じ画面へ並べ、招集パートが`この回答を採用する`から1件を選ぶ。
- 選ばなかった回答は不採用として履歴を残し、重複警告を解消する。

## 3. 修正申請フォーム

### タイトル

`{年度}年度 体育祭 選手登録 修正申請フォーム`

### 冒頭説明

```text
提出済みの選手登録に間違いがある場合に使用してください。

このフォームを送信しただけでは名簿は変更されません。
体育祭スタッフ招集パートが内容を確認し、承認した後に反映されます。
変更前と変更後の情報、修正理由を正確に入力してください。
```

### 申請者情報

通常登録フォームと同じ回答責任者項目を使用する。

### 修正内容

1回の回答で修正できる競技は1つとする。修正する競技を選ぶと、その競技専用ページへ移動し、変更した枠だけでなく競技全体の現在の登録内容を入力する。

| 項目 | 形式 | 必須 |
|---|---|---:|
| 修正対象クラス | プルダウン | はい |
| 修正する理由と変更内容 | 段落 | はい |
| 修正する競技 | 分岐付きラジオ | はい |
| 各枠の登録状態 | ラジオ | 欠員許可時 |
| 各枠の学籍番号 | 記述式 | 設定による |
| 各枠の氏名 | 記述式 | 設定による |

例：リレーを選択した場合は、第1走者から最終走者まで全走者を入力する。送信内容をその競技の完成形として検査し、承認待ちへ保存する。

### 受付停止中

- フォームは常設する。
- 受付停止期間中も回答は保存する。
- 状態を`受付停止中のため保留`とする。
- 自動反映しない。

## 4. 氏名照合ルール

- 学籍番号を主キーとする。
- 半角・全角・改行・タブ・ゼロ幅空白を除去し、全角半角を正規化して比較する。
- 正規化後も氏名だけが異なる場合は警告とする。
- 学籍番号が存在しない場合はエラーとする。
- 学籍番号の所属クラスが登録対象と異なる場合はエラーとする。

## 5. 回答取込

- 生成時に通常・修正フォームへインストール型のフォーム送信トリガーを設定する。
- 回答は最初に`フォーム回答原本`へJSONで保存し、取込失敗時もフォーム上の回答と原本を失わない。
- `form_id`と`item_id`から`フォーム項目対応表`の`field_key`を求め、表示名に依存せず内部項目へ変換する。
- 通常フォームは回答された学年ページの全競技を1件の`INITIAL`申請として保存する。
- 修正フォームは選択された1競技の全枠を1件の`CORRECTION`申請として保存する。
- 保存後に自動検査し、`承認待ち`、`申請項目`、`検査結果`、操作画面の件数を更新する。
- 同じ`form_id`と`response_id`は二重に取り込まない。
- フォーム送信では`登録データ`と帳票を変更しない。
- 修正理由は回答原本に保持し、申請詳細に表示する。

受け入れ条件:

- [x] 通常フォーム回答が承認待ちへ保存される。
- [x] 修正フォーム回答が競技全枠を持つ承認待ちへ保存される。
- [x] 回答取込後に自動検査される。
- [x] 二重取込を防止する。
- [x] 取込失敗時も回答原本が残る。
- [x] 原本保存前のトリガー失敗や処理エラーを、フォーム上の回答から再取込できる。
- [x] 送信だけでは正式データ・帳票が変わらない。
